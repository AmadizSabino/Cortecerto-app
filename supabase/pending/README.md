# Migrations still to run

`0003_to_0016.sql` holds every migration after 0002 in one file, for the live
project, which has run 0001 and 0002. In Supabase, open SQL Editor, paste the
whole file and press Run. It runs as one transaction: if anything fails,
nothing is applied, and you can send the error message to fix it.

Before running it, enable **pg_cron** in Database > Extensions so the nightly
jobs (forget inactive clients, trim error reports) are scheduled. Without it
everything else still works.

After it has run, new migrations are run one by one from `../migrations/`.
The file is generated by `scripts/bundle-migrations.sh`; CI checks it is up to
date and that it applies cleanly on top of 0001 and 0002.
